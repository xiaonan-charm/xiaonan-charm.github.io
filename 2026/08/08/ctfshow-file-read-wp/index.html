前置知识：文件路径是什么？

打个比方，我电脑上的文件夹结构像一棵树：

  • /flag.txt 是绝对路径——从根目录开始一路找过去
  • ../ 是返回上一层——相当于文件管理器里的”后退”按钮
  • 网站代码在 /var/www/html/，它和 /flag.txt 不在同一个文件夹里

总结

  1. 报错信息会泄密——PHP 的 Warning 直接把代码路径和函数名暴露了，这是信息收集的重要一步

  2. 黑名单过滤不靠谱——只封”开头”是封不住的，换种写法就能绕过去。正确的做法是：

    • 直接禁止用户输入路径，只让选文件 ID
    • 或者用 basename() 把路径符号全部过滤掉，只留纯文件名

一些问题

Q1：怎么知道要故意输入一个不存在的文件名（比如 test123.txt）？

这是 CTF 里很常用的技巧——报错信息收集。故意让程序出错，看它返回什么信息。很多网站上线时没有关闭 PHP 的错误显示，一旦触发 Warning 或 Fatal Error，就会把代码路径、函数名甚至数据库信息直接暴露在页面上。这里输入一个不存在的文件名，file_get_contents() 找不到文件就会报错，从报错里我知道了：后端语言是 PHP、用的函数是 file_get_contents()、代码位置在 /var/www/html/index.php。换别的名字比如 aaa、foobar 效果都一样，关键不是文件名，是触发报错。

Q2：代码在 /var/www/html/index.php，flag 也在这个文件夹里吗？

不是。flag 的位置题目一开始就提示了——/flag.txt，注意它开头是个 /，表示它在根目录下。代码路径告诉我的不是”flag 在哪”，而是”我当前站在哪”。知道了自己的位置，我才能算出来需要往后退几层才能到达根目录，然后拿到 flag。就像你迷路了，要先搞清楚自己在地图上的位置，才知道往哪走。

Q3：../ 是什么意思？

../ 表示返回上一级文件夹。这是操作系统内置的规则，每个文件夹里都有两个隐藏条目：. 指向自己，.. 指向父目录。所以当你写 ../，操作系统就会去查”我上一级是谁”，然后从那里继续往下走。Windows 里也有同样的东西，只是用反斜杠 ..\ 表示。

Q4：为什么是 ../ 不是别的符号？

这是 Unix 系统诞生时就定下的约定，就像红灯停绿灯行，没有为什么，大家都这么认。1970 年代 Ken Thompson 和 Dennis Ritchie 写 Unix 的时候，觉得用 .. 表示上级目录很直观（两个点，比一个点”多一点”），就一直沿用到今天。

Q5：为什么要退三层？

代码在 /var/www/html/，flag 在根目录 /，中间隔了三层文件夹：html → www → var → /。每层需要一个 ../ 来后退，所以需要三个 ../，再加上 flag.txt，完整的路径就是 ../../../flag.txt。

Q6：为什么加 x/ 就能绕过过滤？

程序员写的过滤逻辑大概是”如果路径开头是 / 或 ../ 就拦截”，它只看开头几个字符，不检查中间。我写 x/../../../../flag.txt，开头是 x/，不是 / 也不是 ../，直接放行。但操作系统解析路径时是从左往右完整处理的，x/ 后面紧跟着 ../ 就会退回去，所以 x/ 的存在对最终结果没有任何影响，只是一个幌子。

Q7：那用 m/、abc/ 行不行？

行，任何不是 / 或 ../ 开头的都可以。x/、m/、1/、随便/ 效果完全一样，只是骗过滤器的，不重要。

Q8：x/ 这个文件夹根本不存在，为什么能打开？

file_get_contents() 会把整条路径交给操作系统去解析，操作系统是按顺序从左往右处理路径的。它看到 x/：”要进 x 文件夹”，然后立刻看到 ../：”哦，退回去”。它还没真正尝试进入 x 就已经被 ../ 带走了，所以 x 存在与否根本不重要。就像导航里规划路线”往前 100 米 → 掉头 → 右转”，导航不会先去验证那条路上有没有路，它只按指令到达终点。
