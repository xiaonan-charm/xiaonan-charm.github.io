LFI-01 php://filter 读取源码

Created2026-07-31|Updated2026-07-31|学习日志
|Post Views:

前置知识：为什么不能直接读 PHP 文件

PHP 文件和 HTML 文件有一个关键区别：PHP 会被服务器执行，HTML 不会。

如果我直接让服务器读 index.php，PHP 引擎会执行里面的代码，把执行结果（HTML 页面）返回给我，而不是源码本身。这就是为什么我在输入框里填 index.php 什么也看不到——代码跑了，但我不想让它跑，我想看它写的是什么。

解决办法是：在读文件之前，先给内容套一层编码。 编码后的内容对 PHP 引擎来说就是一串无意义的字符，不会触发执行，原样返回给我。我拿到编码结果后自己解码就行。

这个”边读边编码”的工具就是 php://filter。

php://filter 核心公式

拆开来看：

部分 做什么
php://filter 告诉 PHP：我要用流过滤器来读文件
convert.base64-encode 过滤器：在读取时把内容转成 base64
resource=xxx 指定读哪个文件

选 base64 这个过滤器有一个额外好处：base64 编码后的字符只有 A-Za-z0-9/+=。有些题目会对输出内容做正则验证，base64 的字符集极小，很容易通过。

做题思路（适用所有 LFI 题）

看到 LFI 输入框，我脑子里就走三步：

先侦察，再攻击。 不要上来就猜 flag 藏在哪个文件里。先读 index.php——它一定会告诉我下一步往哪走。

Step 4：拿到 flag

为什么 include 后面的文件一定是线索

include "文件名" 在 PHP 里的行为是把另一个文件的内容拉进来一起执行。这意味着：

  • 出题人主动把这个文件的名字写在了我能读到的源码里
  • 这个文件被主程序引用，说明里面有主程序需要的东西（配置、函数、数据）
  • 如果里面有敏感信息，就可能是 flag

源码里每一个 include / require，都是出题人留给我的免费提示。 看到就立刻去读。

常见变体与绕过

做多了之后会遇到出题人加的各种限制，整理如下：

限制 绕过思路
过滤 php:// 关键字 尝试大小写变形、编码绕过
过滤 base64 换别的过滤器，如 convert.quoted-printable-encode、string.rot13
输出做正则验证 选一个输出字符集刚好能通过验证的过滤器
禁止读 .php 后缀 尝试不加后缀名、或用路径截断
文件名固定，不能改 尝试目录穿越 ../../ 配合 php://filter

一条思路记住： 先读 index.php 侦察，再顺着 include 线索往下挖，别上来就猜文件名。
