前置知识：浏览器是怎么工作的

每个网页由三种文件构成：

文件类型 做什么
HTML 页面的结构——文字、按钮、输入框
CSS 页面的外观——颜色、大小、位置
JS（JavaScript） 页面的行为——点击后发生什么、数据怎么验证、请求怎么发送

如果一个网页有交互逻辑（比如”判断分数是否达到 1000 分”），这个逻辑必定写在 JS 文件里。所以排查题目时第一步就是找 JS 文件。

第一步：找 JS 文件

Ctrl+U 查看页面源码，找到所有 JS 引用：

我是如何快速锁定 challenge.js 的：

一、文件名含义。challenge 意思是”题目”，这表明它是靶场作者自己为本题编写的文件。game.bundle.js 中的 game 是游戏、bundle 是打包，这是游戏引擎代码。找题目逻辑优先看题目命名的文件。

二、文件体积。点开 game.bundle.js 有几千行压缩代码，challenge.js 只有几十行、格式整洁。体积小意味着我能快速通读，不用在几千行里大海捞针。

三、注释和风格。challenge.js 开头有中文注释，显然是人手写的；game.bundle.js 是机器打包生成的，读起来费劲。

如何判断一个 JS 文件是第三方库还是靶场自己写的：

方法一：看文件名。jquery、bootstrap、vue 这些是全球知名的开源项目名，如果文件名包含这些词，说明是引入的外部库，不用管。challenge 没有任何开源项目叫这个名字，说明是靶场自己写的。

方法二：点开文件看一眼开头。第三方库通常是几千行压缩代码，开头有版权声明；靶场自己写的文件一般只有几十行，格式整洁，有中文注释。

为什么 readable-check-v2 暗示了核心验证逻辑：

版本号拆开来看：20260725 是日期（2026年7月25日），readable 意思是”可读的”，check 意思是”检查/验证”，v2 是第二版。这几个词连起来说明出题人在 7 月 25 日把验证逻辑改写成了更清晰可读的版本。既然”check”在这个文件里，那题目验证的代码就在这里，不是别处。

第三步：识别漏洞点

漏洞 1：window.getFlag = getFlag

window 是浏览器中的全局对象。所有在 Console 里能直接调用的东西，比如 alert()、console.log()，本质上都是挂在 window 上的，完整写法是 window.alert()、window.console.log()，只是浏览器帮我省略了前面的 window.。

当出题人写了 window.getFlag = getFlag，就是把 getFlag 这个函数注册到了全局。这意味着我在 Console 里直接输入 getFlag(1000) 就能调用它。

如果这行代码不写，getFlag 就只是一个局部函数，我在 Console 里调不到它。

关于 window.xxx：是不是挂上去就能在控制台调用？

是的。只要挂在 window 上的，就能在 Console 里直接调用。Console 默认就在 window 的作用域里：

不仅是出题人挂的，浏览器自带的所有函数也挂在 window 上：

我在 Console 里从来不写 window.alert() 而是写 alert()，就是因为 window. 被省略了。出题人把 getFlag 也挂上去之后，它就跟 alert 一样，变成全局可调的函数了。

漏洞 2：score 是参数，不是从游戏状态读取的

getFlag(score) 需要我自己传入 score。我传多少它就用多少做判断，没有从游戏引擎里读取真实分数。这等于分数的控制权在我手里。

漏洞 3：服务器端没有独立校验

请求体 { action: "claim" } 中完全没有传递分数。服务器收到这个请求后直接发 Flag，不检查玩家到底有没有打够 1000 分。

正确的做法应该是服务器自己存一份分数，收到请求后对比，分数不足就拒绝。但这里验证只存在于客户端 JS 中，服务器处于无脑信任的状态。

这算前端吗？和 Python 写的有什么区别？

这道题的验证代码属于前端。JS 在浏览器里跑，是前端代码。

前端 JS 后端 Python
在哪里跑 我的浏览器（我的电脑上） 服务器（别人的电脑上）
我能看到源码吗 能，F12 直接看 不能，除非作者开源
我能改吗 能，Console 随便改 不能，我没有访问权限
数据验证可信吗 不可信，我能绕过 可信，我碰不到

这道题之所以能绕过，正是因为验证代码在前端（JS），不在后端（Python / Node.js / Java 等）。如果验证写在服务器上，我打不开、看不到、改不了，就必须老老实实打 1000 个僵尸。

核心结论

客户端（浏览器中的 JS）对用户是完全透明的。我能看到代码、能修改代码、能在 Console 里调用任何全局函数。所有关键验证逻辑必须在服务端独立再做一遍，不能只依赖客户端。
